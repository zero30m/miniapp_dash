*2.0和3.0版本中主要存在的问题是：
1. 我们发现小程序页面可以直接被分享到朋友圈，我们不想通过绘制海报等形式进行裂变，而是采用分享到朋友圈的形式实现裂变。--在3.0版本中进行了说明，忽略3.0版本中的分享失败降级功能
2. 在2.0版本中存在随着打招呼人数解锁的’成就系统‘，但我们不需要这个系统，因此这个系统你需要砍掉。
3. 现在小程序没有办法调用接口获取用户的昵称和头像，只能让用户自己填写。但是用户自己填写的话就会造成转化链条过长的问题，因此你需要考虑在页面中砍掉比如微信昵称/头像相关的展示
4. 小程序在微信内推送服务通知也过于麻烦，你也需要砍掉
5. 关于Hi的交互方案，我们想了一种新的方案：用户长按蓄力发射一道激光，然后激光移动变成好友星系里的一颗星星（参考2.0版本中的相关描述），但是除了发起人外其他人不可见有多少星星，因此其他星星应该做成一闪一闪的效果。发起人视角下可以旋转拖动星系（类似3D的地球仪效果），其他人视角下不可以旋转拖动。
6. 对于特殊卡牌的集成部分，特殊卡牌不计入历史记录和剩余牌数指示器，类似一次性卡牌，划过后也无法通过滑动到上一张再次切换到特殊卡牌

限制项	影响	解决方案

6.3 单页模式适配
场景值判断：

// pages/viral/landing.js
onLoad(options) {
  const scene = wx.getLaunchOptionsSync().scene;
  
  // 场景值 1154 = 朋友圈单页模式
  if (scene === 1154) {
    this.setData({ isSinglePageMode: true });
    this.loadSinglePageData(options.initiator);
  } else {
    this.setData({ isSinglePageMode: false });
    this.loadFullPageData(options.initiator);
  }
}
单页模式数据加载（未登录访问）：

async loadSinglePageData(initiatorId) {
  // 云开发需开启"未登录访问"
  const db = wx.cloud.database();
  
  // 仅读取公开数据，不涉及用户隐私
  const result = await db.collection('ViralFriendship')
    .where({ initiatorOpenId: initiatorId })
    .count();
  
  this.setData({
    hiCount: result.total,
    initiatorInfo: await this.getInitiatorPublicInfo(initiatorId)
  });
}

8.5 落地页双模式代码架构
// pages/viral/landing.js
Page({
  data: {
    isSinglePageMode: false,
    initiatorInfo: null,
    hiCount: 0,
    hasInteracted: false
  },
  onLoad(options) {
    const scene = wx.getLaunchOptionsSync().scene;
    const isSingle = scene === 1154;
    
    this.setData({ isSinglePageMode: isSingle });
    
    if (isSingle) {
      // 单页模式：仅展示+引导
      this.initSinglePageMode(options);
    } else {
      // 完整模式：完整交互
      this.initFullMode(options);
    }
  },
  async initSinglePageMode(options) {
    // 调用无需登录的云函数
    const res = await wx.cloud.callFunction({
      name: 'getViralPublicInfo',
      data: { initiatorId: options.initiator }
    });
    this.setData({
      initiatorInfo: res.result.info,
      hiCount: res.result.hiCount
    });
  },
  async initFullMode(options) {
    // 完整登录流程
    await this.login();
    await this.loadFullData(options.initiator);
  }
})

9.3 运营合规风险
WARNING

微信官方明确提示：滥用分享朋友圈能力用于营销、诱导将会被打击

合规要点：

✅ 单页模式中尽可能呈现完整内容
❌ 不得诱导强制用户点击"打开小程序"
❌ 不得分享立即获得利益的诱导行为
✅ 我们的设计：展示情感共鸣内容，用户自愿点击

*以下是微信相关功能的官方文档说明：
分享到朋友圈
从基础库 2.11.3 开始支持

支持平台：Android、iOS：微信8.0.24及以上版本

可将小程序页面分享到朋友圈。适用于内容型页面的分享，不适用于有较多交互的页面分享。

设置分享状态
小程序页面默认不可被分享到朋友圈，开发者需主动设置“分享到朋友圈”。页面允许被分享到朋友圈，需满足两个条件：

首先，页面需设置允许“发送给朋友”。具体参考 Page.onShareAppMessage 接口文档
满足条件 1 后，页面需设置允许“分享到朋友圈”，同时可自定义标题、分享图等。具体参考 Page.onShareTimeline 接口文档
满足上述两个条件的页面，可被分享到朋友圈。

单页模式
用户在朋友圈打开分享的小程序页面，并不会真正打开小程序，而是进入一个“小程序单页模式”的页面，“单页模式”有以下特点：

“单页模式”下，页面顶部固定有导航栏，标题显示为当前页面 JSON 配置的标题。底部固定有操作栏，点击操作栏的“前往小程序”可打开小程序的当前页面。顶部导航栏与底部操作栏均不支持自定义样式。
“单页模式”默认运行的是小程序页面内容，但由于页面固定有顶部导航栏与底部操作栏，很可能会影响小程序页面的布局。因此，请开发者特别注意适配“单页模式”的页面交互，以实现流畅完整的交互体验。
“单页模式”下，一些组件或接口存在一定限制，详情见下文单页模式下的限制章节
avatar

页面适配
可通过判断场景值等于 1154 的方法来进行页面适配。另外，在单页模式下，可设置顶部导航栏与页面的相交状态，具体参考 navigationBarFit 配置。

还需留意的是，在单页模式下，wx.getSystemInfo 接口返回的 safeArea 为整个屏幕空间。

单页模式下的限制
小程序“单页模式”适用于纯内容展示场景，可实现的交互与接口能力有限，因此存在如下限制：

页面无登录态，与登录相关的接口，如 wx.login 均不可用；云开发资源需开启未登录访问方可在单页模式下使用，详见未登录模式。
不允许跳转到其它页面，包括任何跳小程序页面、跳其它小程序、跳微信原生页面
不允许横屏使用
若页面包含 tabBar，tabBar 不会渲染，包括自定义 tabBar
本地存储与小程序普通模式不共用
对于一些会产生交互的组件或接口，在点击后调用时，会弹 toast 提示“请前往小程序使用完整服务”。为达到良好的用户体验，请注意适配单页模式的接口能力，请勿大量使用被禁用的接口或组件。

运营须知
分享朋友圈能力是为了满足纯内容场景的分享诉求，滥用于营销、诱导等行为将会被打击。

小程序提供的服务中，不得存在滥用分享违规行为。如强制用户分享行为；分享立即获得利益的诱导行为；以及通过明示或暗示的样式来达到诱导分享目的的行为等。详见《微信小程序平台运营规范》
在“单页模式”下，不得诱导或强制用户点击“打开小程序”，应在“单页模式”中尽可能呈现完整的内容
注意事项
低版本微信客户端打开时，会进入一个升级提示页面
不支持在小程序页面内直接发起分享
自定义分享内容时不支持自定义页面路径
存在 web-view 组件的页面不支持发起分享
支持打开开发版、体验版，无权限人员进入时页面会提示无权限
